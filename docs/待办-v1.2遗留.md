# v1.2 遗留待办清单

> 本文件是审计/交付过程中**明确没做完**的事项，全部带现状、原因与验收标准。
> 不是愿望清单：每条都对应《架构审计报告》里的一个编号或交付报告第 7 节。
> 建议按"安全 → 正确性 → 能力"的顺序做。

---

## T1 审批插件侧 4 处 fail-open（对应 F-02 的残余）

- **现状**：`plugins/approval/index.js` 中 `:220` 判定异常 `next()` 放行、`:111` prefix 不匹配静默放行、`:62-75` 清单缺失只 warn、`:196-199` `ctx.on` 不可用时心跳仍在跑但闸门没挂。
- **为什么没做**：Python 侧已 fail-closed 兜住（无活闸门 → 本地令牌），插件侧改动需要改 Node 判定逻辑 + 补 `decision_test.mjs`，属于跨语言变更，单独一提交更安全。
- **建议做法**：判定异常 → 返回 `{kind:'ask'}`；清单缺失 → 对 `mcp__autolearn__*` 一律 ask；`ctx.on` 缺失 → 不写心跳/代际（让 Python 判定为不可用）。
- **验收**：`decision_test.mjs` 增加 4 个用例，断言异常/缺失时都是 ask 而不是放行；端到端跑一次无闸门场景，Python 日志出现 `host_approval_unavailable`。

## T2 robots.txt 遵守（SEC-09）

- **现状**：全仓无 robots 逻辑，README 曾声称遵守；v1.2 已把该声称从 README 里去掉。
- **建议做法**：抓取前 `GET /robots.txt`（按 UA 判定，缓存 24h），`Crawl-delay` 做节流；不可达时按保守策略跳过。
- **验收**：新增 `tests/test_robots.py`，用本地假响应覆盖 allow/disallow/404 三种情况。

## T3 抓取重试与退避（SEC-05）

- **现状**：5xx / 连接重置直接终态，且该来源后续不再重试。
- **建议做法**：408/425/429/5xx 指数退避重试 3 次，尊重 `Retry-After`；失败原因与重试次数写进 `sources.metadata`。
- **验收**：单测模拟 500→200、429+Retry-After；重试次数落库。

## T4 时效巡检修标 stale（P4 原计划第 5 项）

- **现状**：`freshness_status` 只有抓取时的先验，没有定期巡查；检索默认不过滤 stale。
- **建议做法**：新增 `refresh_freshness` 任务（可关），按 `published_at` + 领域半衰期标 stale；检索可选 `exclude_stale`。
- **验收**：造一条 3 年前的资料，跑到巡查任务后 `freshness_status=stale`，检索默认不带它。

## T5 质量权重校准（P6 遗留）

- **现状**：`knowledge/quality.py` 的 8 维权重手工设定，未用标注数据校准；不能作为"质量已验证"的依据。
- **建议做法**：收集 100+ 条带人工判断的样本，做一次权重回归/网格搜索，把结果写进配置而不是硬编码。
- **验收**：校准前后在同一评估集上的排序相关性（Spearman）有可量化提升。

## T6 L5 人工确认门（P6 遗留）

- **现状**：`_mark_evaluated` 按"已 practiced + 无未决冲突 + 本轮评估记录"自动推进，不是人工评审。
- **建议做法**：L5 需要 `verifier=user` 的评估记录，或在 DSH 审批 UI 加"确认评估"动作。
- **验收**：无人工记录时停在 L4；有人工记录后升 L5。

## T7 语义向量（能力短板）

- **现状**：默认 `hashing:hashed-ngram:512`，是特征哈希不是神经向量；`recall@5=1.0 / precision@5=0.625` 来自 6 篇小语料，不能外推。
- **建议做法**：配 `embedding.provider=openai` 或 sentence-transformers，跑 `rebuild_vector_index()`，再用 `evaluation/retrieval_eval.py` 对比基线。
- **验收**：同一评估集上 precision@5 提升且 recall 不降；报告里附前后数字。

## T8 并发写强一致（P7 遗留）

- **现状**：有 `flock`（不支持时降级无锁）+ 写前磁盘对齐，但不是多进程事务隔离；同机多实例高频写仍有窗口。
- **建议做法**：单写入进程（写队列）或改用带事务的客户端；至少给"降级为无锁"加显式告警计数。
- **验收**：两进程各写 200 条，最终索引条数 = 400 且无完整性错误。

## T9 多语言与领域扩展样本

- **现状**：分类关键词中英混排，其他语言未验证；领域注册表机制可用但只有 7 个内置领域。
- **建议做法**：按 `DomainSpec.keywords` 补语言包；用一个真实第三方领域（如 `legal`）走一遍 `register_domain()` 验证"不改核心"。
- **验收**：新增领域只需一个文件 + 一次注册，测试断言分区/模板/schema enum 全部生效。
