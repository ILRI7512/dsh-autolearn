## 1. 优化前后对比（同一脚本、同一语料，v1.1.0 vs v1.2 实测）

测量方式：`/tmp/alwork/compare.py` 分别对 `1141a78` 的 checkout 与当前分支执行：
6 篇文档 → 提取 → 重复提交同内容 → 覆盖写一条 verified → 8 条 query 检索。

| 指标 | v1.1.0 | v1.2 | 说明 |
| --- | --- | --- | --- |
| 覆盖写 verified 后状态 | `pending_verification` / v1 | **`verified` / v3** | 审计 F-01，最严重的一条 |
| 重复提交同内容后条目数 | 7（多写一条） | **6（不重复写）** | F-06 / S-04 |
| 同项目同内容活跃实体数 | 允许多条 | **唯一索引保证 1 条** | v3 迁移 + 写入拦截 |
| recall@5（8 query） | 1.000 | 1.000 | 小语料，已饱和 |
| MRR | 1.000 | 1.000 | 同上 |
| precision@5 | 0.604 | **0.625** | 误召回略降，幅度很小，不能吹 |
| 提取零产出告警 | 无 | 有（warning + reason） | P2 |
| 审批委派判据 | 配置即放行 | **活闸门才放行** | F-02 |
| 预算 snapshot | 恒为 0 | 真实计数 | H-05 |
| 检索跨项目 | 默认全库 | **默认仅 global** | H-06 |

诚实结论：**数据正确性与安全性的提升是数量级的；检索质量只是小幅改善**，
因为默认向量器仍是特征哈希（见第 7 节）。

## 4. 升级步骤

```bash
git fetch && git checkout optimize/v1.2-audit    # 或合并后的 main
pip install -r dsh_autonomous_learning/requirements.txt   # mcp 仍需 1.x
python -m pytest dsh_autonomous_learning/tests -q          # 期望 197 passed
# 首次启动自动迁移；建议先备份：

```

升级后**建议做一次** `rebuild_vector_index()`：内容指纹语义从"文档+正文"改为"纯正文"，
旧向量仍可用但口径不一致；重建后与去重/缓存口径统一。

## 5. 回滚方案

| 层 | 做法 |
| --- | --- |
| 代码 | `git revert` 对应 commit，或切回 `main`（`1141a78`） |
| 数据 | v3 只把重复片段**标记**为 superseded（不删除），回滚后可 `UPDATE chunks SET invalidated_at='', status=<原状态> WHERE ...` 复原；v4-v7 只加列/表，旧代码忽略即可 |
| 向量 | 回滚后 `rebuild_vector_index()` 重建；或从备份 `restore(db_file=..., manifest_path=...)` |
| 配置 | 新增字段都有默认值，旧配置文件无需修改 |

回滚风险最高的是 P3（领域注册表）：`core/models.Partition` 只剩 4 个基础设施分区。
若外部代码引用了 `Partition.UIUX` 等成员，回滚到 v1.1.0 前需检查；仓库内已无引用。

## 8. 安全说明（变更后）

- 审批：环境变量/配置只表达意图，**唯一判据是活闸门**；探测异常、代际标记损坏一律 fail-closed；
- 令牌：不再进入模型上下文；CLI 批准强制交互终端；
- 网络：只允许公网地址 + 白名单端口，每一跳重定向复检；content-type 白名单；
- 写入：`WRITE` 风险也校验 `path_allowed`，导出/备份/恢复都走 `_require`；
- 执行：代码执行仍为**进程级隔离，不是安全沙箱**（这一点没有变，也不该被解读为变强）；
- 日志：JSONL 只记 id/计数/耗时/状态，不记正文。

## 9. 一句话总结

v1.1.0 是"能演示的原型"，v1.2 把**数据不会被静默破坏、审批不会静默放行、
预算不会静默为零、学习结果不会静默归零**这四件事做实了；
检索质量与语义能力仍是已知短板，且已用可重复的评估集量出基线（recall@5 1.0 / precision@5 0.625）。
