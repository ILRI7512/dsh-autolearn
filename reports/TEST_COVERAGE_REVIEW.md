## 3. 测试质量问题（实际检查）

| 检查 | 结论 |
| --- | --- |
| 只验证 mock？ | 核心测试用真实 SQLite/真实文件/真实 HTTP 本地服务；MCP 用真实子进程。mock 仅用于无（模型未实现）。 |
| 无断言测试？ | 未发现；每个用例有 assert。 |
| 只检查返回值不检查副作用？ | 多数关键用例检查 DB/索引副作用；本轮补充了“删除后 chunk 仍存在”“注入后状态仍 unverified”。 |
| 依赖运行顺序？ | 每个用例独立临时目录/引擎；HTTP 用例共享端口但串行并关闭 server。 |
| 依赖外部网络？ | 否（本地回环 + 白名单端口）。 |
| 不稳定测试？ | 性能脚本依赖设备；测试套件中无时间断言。HTTP 端口用 8443（8080 被占用）。 |
| 私有实现细节？ | 有少量直接操作 DB（测试夹具），用于构造边界；主要断言走公开服务。 |
| 契约验证 | 原生工具/ctx 形状、MCP 协议、CLI 退出码均有。 |
| 通过但功能不可用？ | 审计中发现的 6 个缺陷都逃过了旧测试（覆盖缺口），本轮已补回归测试。 |

## 5. 未覆盖 / 建议后续补

1. 真实外网抓取（需要可控目标，避免把公网当测试依赖）。
2. 磁盘写满 / 文件句柄耗尽 / SQLITE_BUSY 压力。
3. 10+ 进程并发写同一 DB（需要文件锁/租约设计）。
4. 长时间（小时级）内存与缓存增长。
5. PDF/DOCX（功能未实现，无法测）。
6. 模型辅助（无实现，无法测）。
7. MCP 协议 fuzz（畸形 JSON-RPC、超大参数）。
8. DSH 真实 profile 启动（被模型凭据阻塞；当前只有契约级 + MCP 子进程）。

## 6. 结论

测试体系从“覆盖主路径”提升到“覆盖主路径 + 关键安全/一致性缺陷 + 真实 HTTP 行为”。仍没有真实外部服务与长稳测试，因此不能宣称“生产级全覆盖”；这些限制在 `FINAL_REPORT.md` 中保留。
